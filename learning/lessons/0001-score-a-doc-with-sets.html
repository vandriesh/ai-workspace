Score a doc with sets

By the end you will have written the scoring half of tsbuddy-ai's retrieval yourself, without AI, and a test suite will confirm it.

Why this function

Corpus.search in tsbuddy-ai/app/corpus.py is the R in your RAG: it decides which help docs the model sees first. Its docstring calls it “the v1 baseline that pgvector has to beat”, so it is also the number your embeddings experiment will be judged against. “How does your retrieval work?” is an interview question; after this lesson you answer it from code you wrote.

The whole algorithm, in words:

  1. Turn the query into a set of lowercase words.
  2. Do the same for the doc's title, summary and body.
  3. Count the query words each field shares, weighted 3.0 for the title, 1.5 for the summary and 1.0 for the body.
  4. Sort the docs by score and keep the top five. (That's lesson 2.)

Five moves, from TypeScript

1 · Split text into words

WORD_RE = re.compile(r"[a-z0-9]+")
WORD_RE.findall("Export to Excel!".lower())   # ['export', 'to', 'excel']

That is "Export to Excel!".toLowerCase().match(/[a-z0-9]+/g), with one difference: with no match, Python returns an empty list, where JS returns null. re.findall MDN match The r"…" prefix makes a raw string, so backslashes reach the regex untouched.

2 · Remove duplicates with a set

set(["excel", "export", "excel"])   # {'excel', 'export'}
{"excel", "export"}                 # the same set, written literally
set()                               # the empty set. {} is an empty dict!

Same idea as new Set(…). A set has no order, so it may print in any order. Tutorial §5.4

3 · Keep the shared words with &

{"export", "excel"} & {"excel", "csv"}   # {'excel'}

In TypeScript you'd write new Set([...a].filter(w => b.has(w))). & is intersection, | is union. set types

4 · Count with len()

len({"excel"})   # 1

A function, not a .length or .size property, and the same function for strings, lists, sets and dicts. len

5 · Empty means false

terms = set(WORD_RE.findall(query.lower()))
if not terms:
    return []

This is the start of the real search. An empty set, list, dict or string is falsy, and so are 0 and 0.0. The trap: in JS, [] and new Set() are truthy. truth testing

Check yourself

Predict the answer before clicking. Only your first click counts.

Question 1 
WORD_RE.findall("?!")

findall always returns a list; no matches gives an empty one. The JS habit of guarding against null doesn't apply here, and Python has no ?? anyway.

Question 2 
len({"excel", "export"} & {"export", "csv", "excel"})

& keeps the words in both sets: excel and export. Union, |, would give 3.

Question 3 
len(set("excel"))

A string is a sequence of characters, so set("excel") is its letters: e, x, c, l, with the repeated e collapsed. For a one-word set, write {"excel"}. set(query) instead of set(words) is a real bug that raises no error; the tests catch it.

Question 4

Query "export excel". Title "export-to-excel Export to Excel". Summary "Download your hours as an Excel file.". The body is that summary followed by "Open Reports and choose Export." What is the score?

The title shares 2 words: 2 × 3.0 = 6.0. The summary shares only excel: 1.5. The body shares both: 2 × 1.0 = 2.0. Total 9.5.

Question 5

Using the weights above, a doc titled "Export" (empty summary and body) gets what score for the query "exports"?

Words are compared whole: exports is not export. There is no stemming, so a plural misses. It's a real weakness of this retrieval; keep it in mind for the interview question below.

Question 6 
bool(set())

Empty collections are falsy, which is why if not terms: works. In JS, Boolean(new Set()) is true.

Say it out loud

Answer in about 60 seconds, out loud or in writing, as if in an interview:

“How does tsbuddy-ai decide which docs the model reads? Name one weakness.”

What a strong answer covers
  • Keyword retrieval, with no vectors yet: the query and each doc become sets of lowercase words.
  • The score is how many query words each field shares: title ×3, summary ×1.5, body ×1. Ties are broken by doc id. The top five come back to the model as ids, titles and summaries, and the model calls read_doc for the full page: the agent does its own retrieval.
  • Why start here: it's cheap, deterministic and easy to explain, and it's the baseline embeddings must beat on the evals.
  • Weaknesses: no stemming (exports ≠ export), no synonyms (download vs export), no Romanian, word presence rather than frequency, and weights picked by hand rather than measured.
